# GoldRush2.0编程掘金争夺赛

## 比赛规则

- 战场为 17x17 网格地图，两名玩家各控制两个角色。角色出生点位于主对角线或副对角线的两端。

- 地图上存在障碍物、炸弹及 NPC
  
  - 障碍物所在网格不可到达
  
  - NPC 与玩家角色一样行动，参与金币争夺
  
  - 角色移动到炸弹网格，损失当前持有金币的 X%（向上取整,当前为10%），炸弹消失，角色可继续行动
  
  - 每 Y 轮（当前为20）刷新一次炸弹

- 地图信息
  
  - 全局信息不对玩家公开，每个角色默认视野为以自身为中心的 5x5 区域
  
  - 玩家可花费金币扩展视野范围
  
  - 每 D（当前为5） 轮发布全局各区域的快照信息

- NPC
  
  - 开局时所有 NPC 出生在地图最中央，总数为 A（公测期间为7）
  
  - 每个 NPC 每轮最多移动 B （当前为3）步
  
  - NPC 之间、NPC 与玩家角色之间可重叠
  
  - NPC 参与金币争夺，但不计入选手胜负判定

- 金币生成：
  
  - 中心 9x9 区域每回合随机生成一定数量金币
  
  - 每若干轮在 9x9 区域外随机生成一定数量金币

- 移动与拾取规则：
  
  - 每名玩家的两个角色初始金币均为 0
  
  - 每轮两个角色共分配 S （当前为6）次移动机会，可任意分配。非法移动（越界、碰障碍物、碰其他玩家角色）不执行，后续移动照常进行
  
  - 玩家角色进入有超过 2 个 NPC 的格子时，因拥挤踩踏损失当前 N%（当前为5%） 金币（向上取整）
  
  - 每回合按决策耗时从小到大依次执行移动。同一网格的金币/炸弹由先执行者获取/触发。NPC 行动顺序位于两名玩家之间
  
  - 拾取规则：角色或 NPC 从其他网格移动到有金币的网格，获得该格 C%（当前为65%）金币，向上取整

- 获胜规则
  
  - 每场比赛固定500轮，结束时金币总量最多的玩家获胜。金币总数相等时，P90延迟更低的玩家获胜。

## 编程规则

- 玩家可以用C++或者Python。
  
  - C++：提交选手策略的so文件（详见发给选手的参考代码）
  
  - Python：提供 .py 文件

- 每轮必须正确返回决策（格式非法或运行时错误则直接判负）

- 每轮接口返回内容：视野内网格状态、可见 NPC 信息、双方金币数；每 D 轮额外提供全局区域快照。

选手编程接口如下：

```C++
extern "C" GameOutput moveDecision(const GameInput* input) {     GameOutput output = {};     // 实现决策逻辑 
    return output; }
```

GameInput的结构如下：

```C++
struct Position { int row; int col; };   // 行、列坐标 
 struct NpcInfo {     int id;        // NPC 编号, 跨回合不变; 空槽为 0 
    Position pos;  // NPC 位置; 不可见时 (-1,-1) 
};  struct RegionStat {     int id;              // 区域编号 1-5 
    int enter;           // 窗口内进入该区域的角色次数 
    int leave;           // 窗口内离开该区域的角色次数 
    int gold_generated;  // 窗口内该区域生成的金币总量 
    int gold_collected;  // 窗口内该区域被拾取的金币总量 
    int gold_remaining;  // 该区域地面当前剩余金币 
    int occupants;       // 该区域当前角色数 
};  struct Snapshot {     int window_begin;    // 统计窗口起始轮; 本轮无快照时为 -1 
    int window_end;      // 统计窗口结束轮 
    RegionStat regions[5]; };  struct GameInput {     int round;                       // 当前回合(从 0 开始) 
    int grid[17][17];                // 网格信息, 见下表 
    Position my_units[2];            // 我方角色0、角色1 的位置(row,col) 
    int my_units_gold[2];            // 我方角色0、角色1 各自持有金币 
    int gold_opp;                    // 对手两角色金币总和 
    Position visible_enemies[2];     // 视野内敌方角色位置, 不可见时(-1,-1) 
    int num_visible_npcs;            // visible_npcs 中有效条数 
    NpcInfo visible_npcs[A];         // 可见 NPC 列表 
    int snapshot_valid;              // 1=本轮有新快照; 0=无
    Snapshot snapshot;               // 每若干轮提供一次的全局区域快照 
};
```

- 网格数组grid的定义：
  
  |     |              |
  | --- | ------------ |
  | 值   | 含义           |
  | -5  | 迷雾（视野外）      |
  | -3  | 炸弹           |
  | -1  | 障碍物          |
  | 0   | 空地           |
  | >=1 | 金币（值=该格金币数量） |
  
    补充说明：视野外统一为 -5；NPC 不在网格中标记，通过 visible_npcs 列表提供

- 玩家每轮返回决策信息（GameOutput）：
  
  ```C++
  struct GameOutput {     int actions[S];  // S步动作 
      int k;           // 分割点：角色0走actions[0:k]，角色1走actions[k:S] 
      int order;       // 0=角色0先执行，1=角色1先执行 
      int vp;          // 0=不买，1=买7x7（当前价格为2金币），2=买9x9（当前价格为3金币） 
  };
  ```
  
    每个字段的含义的说明：
  
  |            |         |                                |
  | ---------- | ------- | ------------------------------ |
  | 字段         | 范围      | 说明                             |
  | actions[i] | [0,4]   | 0=上 1=下 2=左 3=右 4=不动           |
  | k          | [0,S]   | 角色0按照a[0:k]行动,角色1按照[k:S]行动     |
  | order      | {0,1}   | 同一玩家内两个角色的执行先后，0=角色0先走，1=角色1先走 |
  | vp         | {0,1,2} | 视野购买，费用在对局结束后结算                |

- Python接口参考：

```Python
class Player:    def MoveDecision(self, game_input):        actions = [random.randint(0, 4) for _ in range(6)]        k = 4          # 角色0走 actions[0:4](4步), 角色1走 actions[4:6](2步)        order = 0      # 角色0先执行        vp = 1 if game_input.snapshot_valid else 0   # 有快照买7x7        return actions + [k, order, vp]
```

- 时间限制：每轮标准限时 300ms，另有 T (当前为60秒）秒总思考时间池。单轮超出 300ms 的部分从池中扣除，池耗尽则判负。
